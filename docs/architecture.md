# Architecture\n\n## Core pipeline\n\n```text\nInput\n  |\n  v\nAgent Context\n  |\n  +--> Scratch Project Loader\n  |      |\n  |      +--> metadata\n  |      +--> project.json\n  |      +--> assets\n  |\n  v\nScratch IR\n  |\n  v\nAgent Planner\n  |\n  +--> feasibility check\n  |\n  +--> generation plan\n  |\n  v\nScratch Builder\n  |\n  v\nproject.json + assets\n  |\n  v\n.sb3\n```\n\n## Opposition policy\n\nOpposition is not a general personality trait.\n\nThe agent should allow ordinary Scratch implementations even when the implementation is verbose, inefficient, or stylistically different from the agent's preferred solution.\n\nThe agent should oppose only when there is concrete evidence that the requested behavior cannot be represented or reliably implemented in normal Scratch capabilities.\n\n## Project ID loading\n\nThe current loader follows Scratch's project-token flow:\n\n1. Request project metadata.\n2. Read the project token.\n3. Request the project JSON using the token.\n4. Enumerate referenced costume and sound assets.\n5. Build a local project representation.\n\nThe loader is isolated behind `src/scratch/project.ts` so the transport can later be replaced by a CORS bridge without changing the rest of the agent.\n\n## AI boundary\n\nThe model should not emit a raw `.sb3` binary.\n\nThe intended boundary is:\n\n```text\nUser request\n    |\n    v\nAgent protocol\n    |\n    v\nScratch IR / plan\n    |\n    v\nDeterministic builder\n    |\n    v\n.sb3\n```\n\nThis keeps archive creation deterministic and makes validation possible.
